## Objectif
Quatre corrections CSS pour l'iPad : (1) le repli de la sidebar (bouton ☰ et repli auto en édition)
fonctionne à **toutes** les largeurs — aujourd'hui la règle `.collapsed` est enfermée dans
`@media (max-width: 900px)` et ne fait **rien** en paysage iPad ; (2) le bouton × de suppression des
motifs de bibliothèque est invisible sans survol ; (3) la barre Safari recouvre le bas de l'app
(`100vh`) ; (4) double-tap/zoom parasites sur l'UI et loupe iOS sur le canevas.

## Décision clé
`DECISIONS.md §D-010`. CSS uniquement, aucun JS : le code JS du repli existe déjà et fonctionne
(`app.js` `btn-sidebar-toggle` et repli auto dans `enterEdit`) — seule la règle CSS est mal placée.

## Étapes
1. Sortir de la media query `@media (max-width: 900px)` la règle
   `#app.collapsed #sidebar { width: 0; padding: 0; border-right: none; overflow: hidden; }`
   et la transition `#sidebar { transition: width .2s ease, padding .2s ease; }` → les rendre
   inconditionnelles (supprimer la media query devenue vide).
2. `body` : remplacer `height: 100vh;` par les deux lignes `height: 100vh; height: 100dvh;`
   (fallback pour navigateurs sans `dvh`).
3. Ajouter un bloc `@media (hover: none) { .lib-item .lib-del { opacity: 1; width: 24px; height: 24px;
   line-height: 22px; } }` — le × est toujours visible et à taille tactile sur écran tactile.
4. Ajouter `touch-action: manipulation;` sur `header`, `#sidebar`, `#edit-palette`, `#selection-palette`
   (supprime le délai de double-tap et le zoom page sur l'UI).
5. Sur `#stage`, ajouter `-webkit-user-select: none; user-select: none; -webkit-touch-callout: none;`
   (pas de loupe/sélection iOS à l'appui long ; `touch-action: none` y est déjà).
