## T-148 — Responsive, PWA, nettoyage

### Objectif
Rendre la nouvelle UI robuste sur **iPad (portrait/paysage)** et **desktop**, finaliser le **plein écran
PWA/safe-area**, et **supprimer le DOM/CSS mort** laissé par la migration.

### Décision clé (D-012 pt 7 réutilisé)
`viewport-fit=cover` + `env(safe-area-inset-*)` sur barres/panneaux/incrustations ; `apple-mobile-web-app-*`
et `manifest.webmanifest` déjà présents — vérifier cohérence avec le nouveau chrome. `inputmode="decimal"`
sur tous les `input[type=number]` (contour, cadre, dpi, packing).

### Lire / Modifier
- Modifier : `index.html`, `src/style.css`, `manifest.webmanifest`.

### Étapes
1. **Safe-area** : appliquer `env(safe-area-inset-*)` sur la barre supérieure, le rail, les incrustations
   flottantes (zoom, barre sélection, barre édition, toast) — reprendre les `calc(18px + env(...))` de la
   maquette. Tester encoche/coins arrondis iPad.
2. **Responsive iPad portrait** : sous ~900px, s'assurer que rail (78px) + panneau (336px) + canevas
   cohabitent ou que le panneau passe en **overlay** au-dessus du canevas (ne pas écraser le canevas à
   < 0). Barres d'édition : défilement horizontal si trop larges (cf. S6). Conserver les cibles ≥44px.
3. **Desktop souris** : la nouvelle UI ne doit pas être cassée ; masquer les aides tactiles redondantes et
   inversement (règles `(pointer: coarse)` / largeur, réutiliser P9·S1). Molette + raccourcis clavier OK.
4. **PWA** : vérifier `manifest.webmanifest` (nom, thème, icônes, display standalone), `theme-color`
   cohérent avec `--surface`/`--ink`, `apple-mobile-web-app-title`. Rien de neuf si déjà conforme.
5. **Nettoyage** : supprimer les nœuds HTML orphelins (ancien `#sidebar`, `#selection-palette`,
   `#edit-mode-banner`, `.hint` header, `#draft-badge`… tout ce que S2-S6 ont remplacé) **après** avoir
   confirmé qu'aucun `getElementById`/`querySelector` de `app.js` ne les cible. Purger le CSS mort
   correspondant dans `style.css`. `git grep` chaque id retiré pour certitude.
6. **Vérif `file://`** : double-clic `index.html` → app complète, polices locales, zéro requête réseau.

### Validation
- Auto (bloque le commit) : `node test/run.js` → vert.
- Humain (non bloquant) : iPad portrait **et** paysage (rien de coupé, safe-area respectée, cibles ≥44px) ;
  desktop souris non cassé ; PWA plein écran ; aucune erreur console (ids morts). → `VALIDATION.md` (P10 · S7).

### Si bloqué
Si le panneau 336px + rail + canevas ne tiennent pas en portrait sans choix de comportement (overlay vs
push) non prévu par la maquette → STOP, signaler pour arbitrage (overlay recommandé).
