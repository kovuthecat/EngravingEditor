## T2 — Le bout de branche et le pied de la radicelle terminale doivent se recouvrir, pas se toucher

### Objectif

`drawWidthAt` effile TOUJOURS la branche jusqu'à un point sur `st.tipLen`, sans savoir qu'un stamp
`terminale` (radicelle, vrille) y est posé ; `poseCalc`, lui, place ce stamp à partir de `widthAt`
(SANS le sur-effilement de pointe qu'ajoute `drawWidthAt` par-dessus, seulement pour le RENDU du
ruban). Les deux valeurs divergent donc exactement sur le dernier `tipLen` : le stamp est positionné
comme si la branche gardait sa largeur naturelle, alors que le ruban RENDU, lui, se referme en
pointe avant d'y arriver — d'où le décrochage visible sur une branche épaisse (constat de cadrage,
radicelle-tip render).

### Décision clé (plus simple que prévu au cadrage)

Pas besoin de reculer l'ancrage du stamp (`addStamp`/`poseCalc` restent intacts) : il suffit de
rendre `drawWidthAt` COHÉRENT avec `widthAt` sur les branches qui portent un stamp terminal — c'est-
à-dire de suspendre le sur-effilement de pointe pour ces branches-là. La branche se referme alors en
bout arrondi (largeur `widthAt` normale, pas de pointe), exactement la valeur déjà utilisée par
`poseCalc` pour placer le stamp : les deux silhouettes se recouvrent naturellement, sans code de
recul supplémentaire.
